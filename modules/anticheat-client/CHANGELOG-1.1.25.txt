Newfies AntiCheat Client / Client Integrity 1.1.25

Compatibility
- Client semantic version: 1.1.25
- Internal protocol: 13 (unchanged)
- Vintage Story networkVersion: 1.1.21 (unchanged compatibility pin)
- Target: Vintage Story 1.22.7 / .NET 10

Performance
- Heartbeat liveness remains every 15 seconds, but periodic telemetry no longer rebuilds the full runtime DLL/hash census when the managed assembly set is unchanged.
- A cheap identity-only assembly marker determines when a full runtime census is actually required.
- Harmony patch telemetry and randomized self-integrity telemetry remain independently refreshed; runtime-census reuse does not freeze patch monitoring.
- Signed build-manifest reads are cached by package/manifest source metadata, avoiding repeated ZIP opens and JSON parsing for unchanged Client Integrity packages.
- SHA-256 streaming now rents pooled buffers instead of allocating a new 128 KB buffer for every file/ZIP-entry hash.
- Directory package hashing reuses one pooled I/O buffer across files, reducing GC pressure on large loose-mod trees.
- Large assembly and Harmony reflection sweeps yield cooperatively so integrity work competes less aggressively with rendering, chunk loading, audio, and networking.
- HarmonyLib reflection entry points are cached after first discovery.

Reliability retained
- Exact duplicate challenges are ignored client-side.
- Newer challenges queue behind an active deep scan instead of being silently dropped.
- Deep scans run on a below-normal background worker after main-thread runtime-surface snapshotting.
- Scan-time heartbeats reuse cached telemetry instead of launching another deep census.
- Fingerprints remain source-signature invalidated and bounded; changed package/file metadata invalidates cached evidence.
- Protocol-13 report hashing, bound heartbeats, server-baseline self-integrity, randomized self-attestation, and player-authorized mod evidence transfer are unchanged.
