# NSS 1.2.38 / MS11 Perf3

Main Suite version remains **1.2.38**. This performance build follows Audit1 and retains all previous .37/.38 protections, rollback, offline inventories, map, Shift+L, profiler and MOTD changes. Targets Vintage Story 1.22.7 and .NET 10. Companion versions and wire protocols are unchanged.

## Changes

- Recovery journals retain their file handles and serialize/append/fsync on a background worker. Durable intent and receipt writes are awaited before each mutation. World changes remain on the game thread, one operation per dispatch, with a 10 ms yield between applied operations. No fsync was removed.
- Recovery checks occupancy, live block/inventory state and changes again after the intent write. Cancelled or conflicting operations with a durable intent retain conservative receipts. This can skip an operation that was never applied; preserve the journal and inspect it rather than deleting receipts blindly.
- Preview validation yields after a cooperative 4 ms budget or 64 operations. Planning and preview report serialization/writes run off the game thread. A single world/API call can still exceed a cooperative budget.
- Recovery reads admit one query per logger, enforce a 30-second query deadline, and interrupt native SQLite with cancellation/progress guards. `/rollback cancel` and shutdown cancel reads/planning. SQLite busy handling and individual native/API calls can delay cancellation; this is not a hard real-time guarantee.
- Selected cells and pre-window baselines are materialized once per query instead of looking up historical snapshots repeatedly for each event/snapshot row. Existing time/area/world filtering, retained later conflicts, caps and ordering remain unchanged. No additional persistent database indexes or schema migration are required.
- Dense OreShield discoveries use a 4 KiB bitset after 256 cells; sparse records remain sets. Recipient snapshots clone compact state. Discoveries are preserved across reconnects.
- A chunk-to-player index targets mined-cell invalidation at owners of that chunk, rather than scanning every retained player.
- OreShield revisions are capped at 16,384 entries. Compaction advances a monotonic epoch, preventing old in-flight revision comparisons from becoming valid again; cached masks refresh as needed. A compaction can temporarily reduce cache hits.
- WebPanel OreShield diagnostics expose discovery chunk/owner records, targeted invalidation work and revision count/compactions. Discovery coordinates are still retained for the runtime; memory can grow with legitimate discoveries, so these changes do not impose a destructive discovery TTL.
- Extracted the HTTP parser and MOTD browser logic into separate source files while retaining embedded deployment. Header scans resume across reads and the parser avoids two full request-buffer copies.
- Centralized runtime release metadata and inject it into the browser, diagnostics and public build labels. Metadata/package checks still validate mod and DLL versions.

## Synthetic evidence

A local in-memory SQLite fixture with 50,000 events, 2,000 snapshots and 500 cells returned identical pre/post rows and ordering:

| Query | Before | Perf3 |
|---|---:|---:|
| Player event history | 9,032.66 ms | 37.63 ms |
| Area event history | 11,418.22 ms | 25.71 ms |
| Player snapshots | 395.90 ms | 12.21 ms |
| Area snapshots | 503.33 ms | 8.33 ms |

The benchmark includes EXPLAIN QUERY PLAN output. Thirty seeded randomized databases also compare all selected values and ordering against the pre-Perf3 SQL for player/area event and snapshot queries.

Constructing 64 dense discovery records of 32,768 cells allocated **71,700,992 bytes** using the previous HashSet representation and **1,095,168 bytes** using compact records. In that run, insertion took 21 ms versus 30 ms; the measured benefit is reduced allocation, not a claimed insertion CPU speedup. Dense retained bit arrays use 4 KiB each, plus object overhead.

These are synthetic local fixtures, not live-server CPU/tick benchmarks. Validate representative worlds, disk latency, logger traffic and player counts before inferring production results.

## Installation

Stop the server, back up world and Suite data, remove the previous Suite ZIP, and install the **1.2.38-MS11-Perf3** Suite ZIP. Do not install Audit1 and Perf3 together. Existing configuration and data are retained; no companion upgrade is required for this pass. Native SQLite remains under `native/runtimes/` for the game loader.

Test recovery on a world copy before restoring production damage. The WebPanel still accepts fixed-length HTTP bodies; proxies must not forward duplicate headers or unsupported chunked framing.

See `VALIDATION-PERF3.md` for verification and `ServerEssentials-1.2.45/tests/runtime/README.md` for runtime commands. The source folder name is retained from the supplied baseline.
