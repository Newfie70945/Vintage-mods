Important release-line note
- This requested 1.2.35 release retains the later MS8, MS9, MS10, and MS11 feature work even though the Suite semantic version was intentionally moved back to 1.2.35.
- Do not interpret this archive as the historical MS7-only 1.2.35 build.

WebPanel Leaderboard
- Leaderboard is present in the authenticated WebPanel TOP BAR through leaderboardTopBtn; it is not a sidebar-only feature.
- Authenticated leaderboard views include Overview, Skills, Playtime, and player progression/profile detail.
- Leaderboard generation starts from Suite all-player history and merges persisted XSkills/XLib disconnected-player skill sets, so known offline players can rank.
- Offline XSkills UIDs are resolved to last-known Vintage Story player names; UIDs are not exposed to browser leaderboard payloads.
- Authenticated leaderboard availability is independent of whether the public Web Map leaderboard is enabled.

Standalone Leaderboard URL
- Authenticated WebPanel supports /leaderboard, /leaderboard/, and /leaderboard.html and opens the top-bar leaderboard view after authentication/session restore.
- Public Web Map supports /leaderboard, /leaderboard/, and /leaderboard.html using the privacy-sanitized public leaderboard feed.
- Public leaderboard-only mode avoids the normal terrain/map polling loop.
- Existing public visibility controls and /webmap live off privacy continue to apply.

Community MOTD 2.1.2 pairing
- MOTD refresh is open-driven rather than a recurring 30-second broadcast to every online player.
- Config save/reload no longer pushes a live MOTD refresh to all connected players.
- Routine MOTD refresh logging remains reduced to avoid recurring console spam.
- The standalone /leaderboard URL can be linked directly from MOTD/community content.

Discord Integration 1.0.8 pairing
- /players and /serverinfo use corrected connected/playing player-state counting with UID de-duplication and fallback handling.
- /date and /serverinfo game time use HH:mm formatting.
- Disabled/stale slash commands respond instead of silently timing out.
- Suite owns the server-side moderation execution path for Discord /ban, /unban, /mute, and /unmute through newfiesse:discord-staff-command.

Player Teleport Consent
- /t2p <player> requires the destination player's consent through /tpaccept.
- /t2m <player> and /t2p <player> share the consent engine.
- Requests expire after 60 seconds.
- Accepted teleports use a 10-second warmup.
- /t2p resolves the destination player's live position at completion and charges cooldown only after successful teleport.
- Existing PacketGuard trusted teleport handling and /back origin recording remain intact.

AFK
- AFK spin is server-authoritative and does not require Server Suite to be installed on the AFK player's client.
- The server rotates the player's authoritative yaw during AFK lock, allowing other clients to see the spin through normal entity replication.
- The optional Suite client camera/orbit effect remains visual polish only.
- NewfiesAfk EnableServerEntitySpin defaults true and uses CameraOrbitSpeedDegreesPerSecond.

OreShield v3
- All protected ore is concealed by default in recipient chunk data, including cave-exposed ore.
- Cave air alone does not authorize a real ore ID.
- Recipient-aware chunk masking runs at the client-aware chunk-send stage.
- Server-side line-of-sight from the authoritative player eye position authorizes one-way per-player discovery.
- Mining has a secure fast-path: protected ore on the newly opened six adjacent faces is authorized immediately for the player who actually broke the block.
- Discovery corrections use recipient-only SetBlocks updates rather than ExchangeBlock.
- No forceSendChunks reveal path remains, preventing the prior black-world/chunk flashing regression.
- Whole-vein reveal defaults off. When enabled, it uses face-connected (6-neighbor) connectivity rather than diagonal 26-neighbor connectivity.
- LOS work is bounded and candidate indexes rebuild on demand after cache/index eviction.
- The authoritative server world is never rewritten by OreShield virtualization.

WebPanel / OreShield telemetry
- Telemetry reflects the current LOS/discovery architecture instead of the removed proximity-radius repair loop.
- Client Integrity 1.1.26 adds acknowledged OreShield client sync; WebPanel now reports sync batches, entries, ACKs, deferred ACKs, resync requests, and vanilla fallbacks.
- Vanilla correction counters remain available for clients that do not advertise the new capability or fail to complete an ACK.
