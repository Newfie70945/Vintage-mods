# Follow-up audit — Suite 1.2.53 / NOS 0.20.18-preview

Baseline: `2637fcc` (Suite panel/map/clumping pass, NOS 0.20.17). Suite build suffix: `ms11-panel-map-clumping-audit1`. Companion implementations and icons are unchanged.

## Fixed findings

1. **Unnecessary dropped-item updates after refused merges.** The native slot may refuse a transfer, for example because of an additional slot-size restriction. The wrapper still marked both item stacks dirty and synchronized them. A native regression fixture reproduces this on the previous code. The wrapper now publishes only changed stack references/counts for completed operations. Exceptional, potentially partial native operations still publish current state and stand down without replay. Item quantities and normal pickup/removal behavior remain native.
2. **Incomplete clumping compatibility coverage.** Added checks for native collectible equality and slot acceptance/space/modification helpers used by merging. Inherited methods are normalized to their declared implementation so Harmony records are inspected consistently. Foreign helper patches block initial activation and are checked during the existing monitor cadence. This is conservative compatibility detection, not isolation from arbitrary mod code or instantaneous protection from late patches.
3. **Malformed JSON reads could appear successful.** A successful HTTP response with invalid JSON was converted into an empty object. Sidebar consumers could consequently derive a healthy/default status from missing fields. Successful JSON GETs now report malformed responses as unavailable/errors. Caller cancellation, read timeout cleanup, HTTP error handling and existing write behavior are preserved.

4. **Vanilla glider movement used walking/falling limits.** Level gliding could select the 24 blocks/second ground envelope, while descending glides used the 22 blocks/second airborne envelope. The native 1.22.7 gliding module can accelerate beyond these limits. A real `game:glider` / `ItemGlider` in an equipped backpack slot plus active gliding now selects a bounded 120 blocks/second compatibility envelope, with two seconds of landing grace while the glider remains equipped. Client flags alone, ordinary contents slots and code-only lookalikes do not qualify. Speed/acceleration windows reset across mode transitions; acceleration within the glide envelope does not accumulate ground-acceleration violations. Excess speed, hard displacement, noclip, packet and action checks remain active. Flight-review noise is suppressed only for equipped active gliding. This is a compatibility allowance, not proof that client movement is legitimate; modified gliders and real-client flight still need field validation.

5. **Degraded speed could bypass the dedicated kick gate through generic risk.** The supplied production history included a `speedEscalationEligible=False` speed row followed by a risk-based kick. That marker previously gated the dedicated repeat-speed path but not generic risk/finding consequences. Speed rows without affirmative healthy-timing eligibility are now review-only throughout risk, correlation and consequence matching. Existing repeat bonuses are attached only to eligible rows, and degraded speed no longer increases the movement-risk accumulator. Healthy, repeated confirmed-speed enforcement remains enabled. The regression exercises the compiled report path and family scorer. This does not automatically erase historical reports or unrelated findings.

## Reviewed boundaries

- Clumping stays optional and off by default, uses native stack limits, matches owners/attributes/cells/dimensions, retains source remainders and removes only emptied entities. The 3,000-drop fixture checks quantity conservation. Survivor-age behavior and implementation exclusions remain documented.
- Export pools retain at most 16 MiB of cached byte buffers per export and release cached references on disposal. Active working rentals are separate from that cache cap. Startup/live/failure cleanup and direct-mode no-loader behavior are exercised by map-memory tests; no forced GC or game-owned pool trimming was added.
- Sidebar requests remain staggered; static retries and read-only timeout semantics retain their previous limits. No additional polling was added.
- Prior anti-cheat behavior is covered by targeted native regressions for collision evidence, server actions, settings preservation, queued actions and OreShield transport. This is not a certification against every cheat or mod interaction.

Validation includes 38 optimizer suites (33 clumping checks including 3,000-drop conservation), 41 compiled collision/glider checks, speed policy/report-path checks, browser fixtures, export-memory checks and an official-server integration run. Real-client glider takeoff/landing on the production modpack is still a field check; no bot/live-player flight session was performed here.

See the release's validation logs for executed results. Component tests and a clean official-server smoke test do not establish live-player TPS gains or universal modpack safety.
