# Seven-mod audit — 2026-10-25

Scope: a targeted cross-module correctness/performance/privacy audit of the current seven-mod source tree, followed by fault-injection, official-engine component tests and a disposable server run. This is not a line-by-line review of every source file or a production performance certification.

## Findings fixed

| ID | Priority | Mod | Finding and correction |
| --- | --- | --- | --- |
| A1 | P2 | Suite / WebMap | An exception before the round-robin cursor advanced kept retrying the same player, starving later players. The cursor now advances in a finally block. Coordinate differences use 64-bit arithmetic so large position changes cannot overflow. |
| A2 | P2 | ChatGuard | A failed configuration write left the new settings active in memory. Settings and mode changes now persist a candidate first, then publish it. Failures retain the previous active configuration. |
| A3 | P2 | ChatGuard | The game-thread world-save handler waited on two disk writers, each with a five-second flush budget. A slow disk could therefore add seconds to a save callback. Autosaves now queue the immutable snapshot without waiting; workers still flush writes and disposal retains bounded shutdown draining. This is not proof that ChatGuard caused a particular historical server stall. |
| A4 | P2 | Anti-Cheat Client | Case-insensitive path cache keys mixed distinct Linux files with matching sizes/timestamps. File, package and manifest path caches now use platform-appropriate comparison; content normalization and protocol rules are unchanged. |
| A5 | P2 | Anti-Cheat Client | Failed package/hash/manifest reads could be cached under an unchanged metadata signature, preventing recovery after a transient lock. Failed reads are returned as unavailable without poisoning the cache; later calls retry. Deterministic missing-manifest results remain cacheable. |
| A6 | P2 | Anti-Cheat Client | Signed ZIP manifests trusted declared sizes before unbounded CopyTo, and loose manifests had no read-size limit. Actual reads now enforce 256 KiB and the declared size, rejecting expanded or truncated entries before parsing. |
| A7 | P2 | MOTD | The logo byte cap and PNG signature did not bound decoded image dimensions. A small compressed image could request a huge native allocation. The server cache and client logo path now check IHDR/dimensions before decoding: <=1 MiB encoded, <=4096 per side, <=4,194,304 pixels total. This checks header/size safety, not the validity of every PNG chunk. |

### Reproduction evidence

- The previous fingerprint helper failed the equal-size/equal-timestamp case-only filename test, returning another file's cached hash. Corrected code passes independent file, package and ZIP checks.
- The previous compiled ChatGuard failed the injected StoreModConfig error test: the active config reference changed despite failure. Corrected code preserves the original reference; a successful retry applies the candidate.
- A deliberately stalled writer verifies the new ChatGuard world-save callback returns without waiting for disk; after releasing the fixture, its queued snapshot persists.
- Translocator tests make the first player's accessor throw repeatedly while the second player discovers a pad. The second player still progresses, hidden targets stay absent from public JSON and disabled tracking performs no world reads.
- Synthetic expanded/truncated manifest streams verify the helper consumes no more than the declared length plus one detection byte. Temporary exclusive file locks verify retries with unchanged metadata.
- Logo tests reject huge dimensions in a small encoded payload, combined pixel-budget overflow and truncated headers while retaining a normal small PNG.

## Validation

- Six ordinary modules build against official Vintage Story 1.22.7 / .NET 10, zero compiler warnings/errors.
- NOS full driver: 35 component/Python suites pass; no NOS feature defaults changed by this audit.
- Twelve compiled/native regression projects pass, including companion audits, HTTP hardening, module/storage safety, anti-cheat cost fixtures, migration pause, 49 translocator checks, native API compatibility, canonical chat/moderation ordering, proximity routing, 42 formatter checks and 30 Discord event checks.
- Additional package/manifest helper tests pass with temporary case-sensitive paths, same metadata, file locks and synthetic streams.
- Chromium regressions cover the translocator layer, incremental tiles, performance refresh, proximity controls, optimizer settings, MOTD editor, memory display and panel lifetimes.
- Disposable official server loads all seven mod IDs, with Discord explicitly disabled. The Suite can read/save ChatGuard settings, run an explicit world save, operate NOS capture controls, toggle/persist the map layer, reject direct private-file requests and shut down cleanly. The copied world passes SQLite integrity checking. No authenticated game players were connected; no live Discord bot was exercised.
- Source/version consistency and whitespace checks pass. Release manifests include source identity, file hashes and per-mod build provenance.

## Remaining limits / follow-up

- No new blocking defect was confirmed in the inspected Discord Link, Player List or NOS paths. Passing these tests is not a guarantee of compatibility with every modpack.
- Full client visual/GL rendering is not covered by headless tests. MOTD's existing minimum layout dimensions may still exceed unusually small effective viewports at extreme GUI scales; that layout should be checked in a real client before a visual reflow.
- The new PNG checks bound dimensions before decoding; the real decoder remains responsible for CRC/compressed-stream validity.
- Production GC pauses, filesystem contention, mod callback costs and memory retention still require representative live captures. This audit does not identify an owner for every historical lag incident or claim a measured production TPS gain.
